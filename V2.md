# Version 2.0: mark tasks as done

Version 2.0 is a separate change on the **`v2`** branch. It adds:

- a `done` boolean column to the `tasks` table
- `PATCH /api/tasks/:id` to set `done` to `true` or `false`
- a **Mark as done** button that strikes through completed tasks
- a safe startup migration so an existing version 1 database keeps its data

No dependencies change. The only code files changed are `server/index.js`,
`client/src/App.jsx`, and `client/src/index.css`. The README API table also gets
the new PATCH row.

## Try the v2 branch

```bash
git checkout v2
npm install
npm run build
npm start
```

Open <http://localhost:3000>. (For development, use `npm run dev` and
`npm run dev:client` as described in the README.)

## Database migration without losing data

Run this once against the existing database:

```sql
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS done BOOLEAN NOT NULL DEFAULT FALSE;
```

This only **adds** a column. Existing rows are kept and automatically get
`done = false`. There is no `DROP`, no table rebuild, and no data loss.

You can run it by hand:

```bash
psql "postgres://USER:PASSWORD@HOST:5432/tasktracker" \
  -c "ALTER TABLE tasks ADD COLUMN IF NOT EXISTS done BOOLEAN NOT NULL DEFAULT FALSE;"
```

For a local database:

```bash
psql -U postgres -d tasktracker \
  -c "ALTER TABLE tasks ADD COLUMN IF NOT EXISTS done BOOLEAN NOT NULL DEFAULT FALSE;"
```

You do not have to run it manually: the v2 server also runs the same statement on
startup, after `CREATE TABLE IF NOT EXISTS`. That means deploying v2 to Render
migrates the Render database automatically.

## Test the endpoint

```bash
# Add a task
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Test v2"}'

# Mark task 1 as done (use the id returned above)
curl -X PATCH http://localhost:3000/api/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"done":true}'

# Mark it as not done
curl -X PATCH http://localhost:3000/api/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"done":false}'
```

A successful PATCH returns the updated task, for example:

```json
{
  "id": 1,
  "title": "Test v2",
  "done": true,
  "created_at": "2026-11-27T09:44:50.349Z"
}
```

## Deploy v2 on Render

Option 1: deploy the branch directly. In Render, open the service, go to
**Settings > Build & Deploy**, change **Branch** to `v2`, and deploy. The server
runs the migration on startup.

Option 2: merge it into `main`:

```bash
git checkout main
git merge v2
git push origin main
```

Render redeploys `main`, and the existing tasks stay in place with
`done = false`.
